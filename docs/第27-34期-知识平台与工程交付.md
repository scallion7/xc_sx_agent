## 一条命令演示

推荐 Python 3.11，新建虚拟环境并安装锁定依赖：

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -m app.scripts.demo_stack --smoke
# 保持服务运行，打开终端打印的 /workspace 与 /workbench：
python -m app.scripts.demo_stack
```

启动器自动使用隔离 SQLite、空库迁移、合成知识种子、独立 API/Worker/受控模型/库存 MCP 进程，动态选择回环端口。演示令牌为 `demo-user` / `demo-admin`，只用于本机沙箱。退出会终止它创建的子进程；`app/sessions/platform-demo` 保存演示数据，可显式使用新的 `--directory` 创建新环境。

客户端操作：连接会话 → 查询“七天退货” → 发送“请为订单 ORD-20240125-006 创建售后工单” → 核对确认卡片 → 确认一次 → 查询工单状态。客服端使用管理员令牌刷新待办，接管相同用户会话、回复、释放。中高风险工单显示风险和证据，审批带 `expected_version`，版本冲突必须刷新。

人工接管与写操作的领取在同一 SQL 事务中争用所有权：已开始的动作使接管返回冲突；接管成功后新写入被阻止，模型完成的结果仅留作受保护内部草稿，不进入客户历史。已被业务系统受理的 Outbox 命令仍需完成对账，接管不是撤销资金的接口。

## 知识发布与检索

导入的租户来自部署配置，不能由文档或模型参数覆盖。元数据含政策类型、地域、渠道、商品范围、起止日期和来源。生产多租户接入仍应按数据库/部署隔离旧业务表；新增平台表虽按 tenant 分区，不能据此宣称整个旧系统已变成共享库 SaaS。

导入任务依次 checkpoint `parse/chunk/embed/ready`，变化内容按 text hash 写 embedding cache；换模型构建新快照时补齐该模型的向量。构建成功后才通过 expected_version 切换 head。默认 30 天可回滚；过期未激活快照可 GC，活跃 head 与配置 manifest 引用受保护。源版本与 chunk 保留用于审计，GC 回收索引快照，不是物理抹除源文档。删除使用 tombstone，旧固定快照与缓存也不得再次返回该文档。

上传上限 10 MB、PDF 200 页、切分 2500 块；加密 PDF、无文本层 PDF 明确拒绝，OCR 不包含在本版。纯 Python/SQL 快照适合演示规模，不等同于分布式向量库。现有 Numpy/Chroma 教学入口仍保留；版本化检索复用 cosine 算法，把不可变索引存 SQL，未引入 pgvector。

默认 `local-hash-256-v1` 是可复现词法投影，**不是语义 embedding**。`jieba-0.42.1-search-v2` 包含明确停用词和离线词法覆盖门槛；BM25 k1=1.2/b=0.75，RRF k=60。reranker 为数字/精确词匹配规则，不能称 cross-encoder。`KNOWLEDGE_EMBEDDING_MODE=openai` 可接真实兼容 embedding；索引模型不匹配会失败关闭。Embedding 的外部费用当前未纳入聊天模型账单，真实导入应单独配置额度与监控。

引用结构校验确保 chunk/version/release 和原文片段存在；不能保证一段生成结论在语义上被该片段支持。政策冲突由相同 policy_key 的不同 decision 明确标注触发，不靠模型推测。需要条件、无证据或冲突时替换成保守答复，业务资格继续由原确定性风险规则决定。

## 预算、配置发布与评测

配额存 SQL，以租户账户串行化额度检查与预留；用户换 API Token 不改变用户账户。RPM 为滚动 60 秒，并发按有效 reservation 统计；token 预算是**累计限额**，不自动按日重置。SDK 重试关闭，网关每次实际尝试分别记录。超时或缺 usage 按预留量计入 `needs_reconciliation`，管理员可通过账单凭证一次性修正。缓存只接受 public_knowledge/retrieval，key 包含租户、知识版本、Prompt、模型、分词版本和检索条件。

`model_catalog.json` 中 demo-small/demo-planner 为演示别名，价格 0 是模拟配置。接真实服务要填写能力、上下文、超时和已核验价格版本；预算控制的是 token，不是承诺固定人民币支出。为长任务配置足够的调用超时与 Worker 租约。

配置 manifest 固定 code_commit、模型配置内容与 hash、Prompt、工具 schema hash、知识快照、风险规则内容与版本、数据集 hash、策略。新会话按稳定哈希分桶，已有会话与运行保留原 manifest；工具代码/schema 不兼容时失败关闭。报告另记录源码树 hash，未提交工作不能伪称一个新 Git commit。

```bash
# 在专用评测数据库、受控 HTTP 模型 URL 下运行。默认仅 10 次；全量离线：
python -m app.scripts.evaluate_platform --agents --max-runs 540 --repeats 3 \
  --token-budget 300000 --output app/sessions/evaluation.json
# 报告与当前数据库的知识 release 必须匹配。先创建 evaluated 配置：
python -m app.scripts.publish_configuration --report app/sessions/evaluation.json
# 要发布时明确给出当前 deployment head 的版本，避免覆盖他人变更：
python -m app.scripts.publish_configuration --report app/sessions/evaluation.json \
  --deploy --expected-version 0
```

生产配置发布要求 live + human_reviewed 的证据；目前合成离线报告不能过该门禁。`--live` 单次最多 10 次任务/20000 token，需要用户另行决定真实模型预算。真实评测只在专用沙箱/评测数据库运行，不回放真实写操作。通过 `--release-id` 评测已创建候选，可保证报告 manifest hash 一致。

## MCP 库存沙箱

注册 `connector_id/url/definitions/policies/expected_version` 到管理员 API。只有审批的只读工具进入模型工具集合；身份 HMAC 包含 tenant/user/permissions/expiry，由系统注入，沙箱独立验签。schema 漂移停用连接器，运行快照固定旧版本。未知工具、伪造身份参数、权限不足、超长输出和超时会明确失败。

库存 reserve/release 写工具走专门适配器：用户提案 → 验证参数 hash 的确认 → 原子写操作记录和 connector_jobs → Worker 先查询稳定预留键 → 必要时执行 → 验证回执所属用户、租户、商品、数量。响应丢失重试仍只扣一次库存；release 恢复库存且幂等。失去租约的旧 Worker 不得提交本地最终结果；耗尽重试进入人工对账。远端不可达只有显式声明语义与数据源等价的本地能力可以接替同名工具。

锁定 MCP 1.30.0：本机原 MCP 2.0 已移除 FastMCP，真实协议测试发现后锁定兼容版本；客户端兼容传输返回的 2/3 元组。依赖升级必须跑真实协议测试。

## Trace、容量与故障

W3C `traceparent` 经提交时 runtime snapshot 传到 Worker；记录 queue wait、run、model、retrieval、tool、SQL checkpoint。退款入 Outbox 时保存上游 trace，独立 dispatcher 恢复它并传到 HTTP Provider。SQL exporter 不记录任意输入、身份或请求体，仅允许有限字段；采样/保留清理不影响业务审计。指标标签不使用 session/run ID。

本机单 Worker、SQLite、受控模型，1/10/50 并发分别一次冷批次，61 个请求均成功。50 并发吞吐约 17.67 次/秒，P95 约 2620 ms；1 并发包含首次初始化开销，不能直接推导伸缩曲线。尚未测到饱和点、长期稳定性、真实模型与远程 PostgreSQL 容量；不得外推生产 SLA。

`drill_platform` 真实杀死领取任务的 Worker，然后通过租约接管完成任务；用 SQLite 排他锁模拟短暂数据库阻断，故障期间返回 500，恢复后同一幂等请求仅一条记录，Worker 继续运行。供应商超时、响应丢失、重复/乱序回调由第 26 期真实 HTTP 回归覆盖。共享配额使用 SQL，因此 Redis 中断不适用。时间戳与最终状态保存在 JSON 报告。

## 交付、升级和恢复

```bash
python -m playwright install chromium
DATABASE_URL=sqlite:///:memory: python -m app.scripts.quality_platform --browser
# 专用测试数据库上执行迁移 / drift / SQL smoke（禁止指向业务库）：
DATABASE_URL=sqlite:////tmp/platform-ci.db python -m app.scripts.quality_platform --database
python -m app.scripts.benchmark_platform --output app/sessions/capacity.json
python -m app.scripts.drill_platform --output app/sessions/drills.json
python -m app.scripts.backup_restore --backup /tmp/platform-backup.db \
  --restore-url sqlite:////tmp/platform-restored.db --report /tmp/platform-restore.json
```

原工作区遗留演示数据库尚无迁移版本，本轮使用隔离新库验收；复用旧数据应先一致性备份，再运行 `python -m app.scripts.manage_migrations upgrade`。

迁移 `20261025_0006` 仅新增表，stage26 业务行保持；旧应用可继续读旧字段。先升级数据库，再滚动升级 API/Worker；回退兼容应用时**保留新表、幂等回执、审计和 Outbox/Inbox**。非空新表拒绝 downgrade，禁止用删除账本实现业务回滚。需破坏性清理时另行迁移。Worker 收到 SIGTERM 停领任务，知识任务在下个 checkpoint 中断并可重试；短 SQL 故障退避重试。

SQLite 使用在线一致备份，恢复到不存在的新路径；逐表比较行数与规范化内容 SHA256，包含业务状态和审计表，并做 integrity_check。PostgreSQL 路径使用 pg_dump/pg_restore，要求单独空数据库和暂停写入后比对，代码已提供、未本机实跑；还需演练跨服务数据库的一致恢复点。哈希验证证明备份与恢复一致，不等同于防篡改审计链。

```bash
# Compose 配置已提供，当前本机无 Docker，以下是待环境核验命令：
docker compose -f docker-compose.yml -f docker-compose.platform.yml \
  --profile integration up --build
# 核心服务需配置真实兼容模型 URL/目录；观测工作台用同一 SQL：
TELEMETRY_ENABLED=true docker compose -f docker-compose.yml \
  -f docker-compose.platform.yml --profile observability up --build
```
