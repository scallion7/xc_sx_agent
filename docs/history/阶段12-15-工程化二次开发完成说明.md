## 2. 依赖与调用方向

```text
FastAPI / CLI / Evaluation
          │
          ▼
  Application Factory
          │
          ▼
 Conversation Agent
   ├─ GuardrailEngine
   ├─ ModelGateway ──> OpenAI-compatible SDK
   ├─ ToolRegistry
   │    ├─ CommerceService ──> CommerceRepository
   │    ├─ AfterSaleService ─> AfterSaleRepository
   │    ├─ KnowledgeService ─> VectorBackend
   │    ├─ MemoryManager
   │    └─ SkillManager
   ├─ SessionRepository
   └─ EventBus ──> CLI / JSONL / Metrics / SSE / WS / Eval
```

业务 Agent 只依赖协议和应用服务。模型 SDK、SQLAlchemy 和文件存储位于基础设施或
适配器层。

## 3. 数据与状态

SQLAlchemy 元数据包含：

- `sessions`：以 `(session_key, user_id)` 组成复合主键；
- `after_sale_cases`：工单状态、用户、订单和完整领域载荷；
- `orders`：用户归属、订单状态、金额和业务载荷；
- `products`：商品检索数据；
- `logistics`：订单与物流轨迹；
- `refunds`：退款编号、用户、原因、状态和时间。

`SqlCommerceRepository` 会在演示模式下幂等写入种子数据。退款申请会创建退款记录并
把订单状态改为 `refund_processing`；重新创建进程后仍可读取，重复申请会被幂等阻止。

## 4. API

| 接口 | 权限/用途 |
|---|---|
| `GET /health` | 健康检查 |
| `POST /v1/chat` | 鉴权后的同步聊天 |
| `POST /v1/chat/stream` | 实时 SSE Agent 事件与最终结果 |
| `WS /ws/events/{session_id}` | 当前用户会话的实时事件 |
| `GET/DELETE /v1/sessions/{session_id}` | 用户隔离的会话读写 |
| `GET /v1/orders`、`GET /v1/orders/{id}` | 当前用户订单 |
| `GET /v1/products` | 商品检索 |
| `GET /v1/after-sales/{id}` | 用户隔离的工单查询 |
| `GET /v1/events` | 用户事件或管理员全局事件 |
| `GET /v1/admin/after-sales/pending` | 管理员审批队列 |
| `POST /v1/admin/after-sales/{id}/review` | 管理员批准/拒绝 |
| `GET /v1/admin/metrics` | Token、延迟、事件和工具成功率 |
| `GET /v1/admin/regression` | 最新离线评估摘要 |
| `GET /admin` | 轻量客服管理台 |

SSE 使用按 `trace_id` 过滤的队列订阅器，在 Agent 运行期间逐事件输出，而不是结束后
回放缓存。WebSocket 使用按用户会话过滤的队列订阅器。

## 5. 安全边界

1. API Token 映射为 `user` 或 `admin` 角色及权限集合；
2. 会话、订单、退款和工单都在业务层再次检查 `user_id`；
3. Prompt Injection 在任何模型调用前确定性阻断；
4. 敏感数据在进入模型、会话文件、事件日志和最终响应前脱敏；
5. `apply_refund` 与 `execute_after_sale_case` 要求显式工具权限；
6. 启用售后工单时，模型看不到旧的直接退款工具；
7. 人工审批不是模型工具，只能从管理员 API 或独立审批脚本触发。

## 6. 可观测性与评估

每个事件包含时间、`trace_id`、`session_id`、`user_id`、来源和结构化数据。
模型事件记录 Token、延迟和重试，API/CLI 创建的 Agent 共用应用级滑动窗口限流器；
工具事件记录来源、成功/失败和延迟；指标聚合器
计算工具成功率。评估沙箱订阅同一 EventBus，不再 monkey patch 模型客户端。

离线评估报告默认写入 `EVAL_REPORT_PATH`，管理台只读取摘要。真实模型评估与
LLM-as-Judge 是显式命令，不属于本轮自动验收。

## 7. 无真实模型验收

本轮自动测试全部注入 `tests.fakes.FakeOpenAI`，覆盖：

- 多实例 ToolRegistry 隔离和用户订单归属；
- 模型网关超时参数、重试及事件；
- 工具成功/失败、权限和敏感事件脱敏；
- Prompt Injection 在零模型调用下被阻断；
- 敏感输入在模型上下文和会话持久化前被脱敏；
- SQL 会话、退款和工单的持久化、幂等与用户隔离；
- Policy reranker、政策失效过滤和风险规则版本；
- 缺少向量索引时的离线词法检索降级；
- FastAPI 鉴权、聊天、SSE、订单、工单、审批、指标和回归接口；
- 评估沙箱通过事件采集 Fake 模型 Trace；
- Docker Compose 的 API/PostgreSQL 服务和健康配置。

推荐验收命令：

```bash
python -m unittest \
  tests.test_secondary_development \
  tests.test_architecture \
  tests.test_agent_deepening -v
```

该命令不会访问真实大模型。

## 8. 部署边界

原规划功能已经完成，但生产部署仍应由使用方完成以下环境治理：

- 用 OAuth2/OIDC 和密钥管理替换演示 Token；
- 使用受控数据库迁移与备份恢复流程；
- 关闭演示种子并接入真实订单主数据；
- 由法务、风控与客服运营审核政策和风险规则；
- 在目标模型、网络和数据规模上另行做质量、成本、容量及灾备测试。
