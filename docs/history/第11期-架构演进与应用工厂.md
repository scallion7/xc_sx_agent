# 第 11 期：架构演进与应用工厂

> 历史归档：记录当时的设计、实现与验收范围，不代表当前运行状态。当前入口见 [文档导航](../README.md) 与 [验收状态](../evaluation/acceptance.md)。原始证据保持原版本，不追改历史测量结果。

## 目标与结果

本阶段建立了可持续替换旧实现的稳定接缝，并为阶段 12–15 的工程化改造奠定基础：

1. 单 Agent 与 Multi-Agent 共享 `BaseConversationAgent`；
2. 配置、模型网关和事件总线可以按实例注入；
3. CLI、API 和评估统一通过 `app.bootstrap.create_agent()` 创建 Agent；
4. 评估环境使用配置副本，不修改全局配置；
5. 原有 `EcomAgent()`、`MultiAgentOrchestrator()` 和 CLI 入口保持兼容。

## 当前分层

```text
CLI / FastAPI / Evaluation
            │
            ▼
  app.bootstrap.create_agent
            │
     ┌──────┴──────┐
     ▼             ▼
 EcomAgent   MultiAgentOrchestrator
     └──────┬──────┘
            ▼
 BaseConversationAgent
   ├─ ModelGateway
   ├─ EventBus / TraceContext
   ├─ GuardrailEngine
   ├─ SessionRepository
   ├─ Memory / Skills
   ├─ CommerceService
   ├─ AfterSaleService
   └─ ToolRegistry
```

`BaseConversationAgent` 管理公共生命周期，不决定路由或工具调用策略。替换 ReAct、
Router、存储或模型供应商时，不需要复制会话、记忆和安全逻辑。

## 统一创建入口

```python
from app.bootstrap import create_agent

single = create_agent(mode="single")
multi = create_agent(mode="multi")
automatic = create_agent(mode="auto")
```

离线测试或私有部署可注入配置、模型客户端、`ModelGateway` 和 `EventBus`：

```python
agent = create_agent(
    mode="single",
    config=runtime_config,
    client=fake_or_compatible_client,
    event_bus=event_bus,
)
```

## 兼容策略

- 原有构造方式继续有效；
- `EcomAgent.messages` 继续返回完整模型上下文；
- JSON 会话和工单仓储保留为本地适配器；
- 旧的工具函数入口保留，但 Agent 运行时使用实例级服务；
- `ToolManager` 独立构造时仍有默认配置，应用工厂始终显式注入。

## 后续路线完成状态

### 阶段 12：实例级工具注册——已完成

`ToolRegistry` 实例替代 `_TOOL_MAP` 和 memory/skill setter；Memory、Skill、
Knowledge、Commerce 和 AfterSale 处理器通过闭包绑定到当前 Agent，不会在多个实例
之间相互覆盖。

### 阶段 13：模型网关——已完成

`ModelGateway` 把 OpenAI SDK 移出业务 Agent，统一超时、指数退避重试、滑动窗口限流、
Token/延迟/工具调用指标和错误事件。测试使用 Fake 客户端，不访问外部模型。

### 阶段 14：事件与可观测性——已完成

核心模块通过 `EventBus` 发出模型、工具、路由、历史压缩、安全和 MCP 事件。
CLI、JSONL、内存指标、SSE/WebSocket 以及评估 Trace 均作为订阅器接入。

### 阶段 15：服务化与持久化——已完成

FastAPI 提供 REST、SSE、WebSocket 和管理后台；会话、售后工单及电商业务数据均通过
Repository/Service 分层，可使用 SQLite/PostgreSQL。JSON 与 Mock 只作为兼容适配器。
