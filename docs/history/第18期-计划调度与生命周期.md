## 1. 有限并发调度

- 调度器按依赖层选择当前可运行步骤；
- 同一依赖层中互不依赖的只读步骤可并发执行；
- 副作用工具始终串行，不进入并发线程池；
- `PLAN_MAX_CONCURRENCY` 控制最大并发数，默认值为 `3`；
- 执行完成顺序不影响最终结果顺序，结果仍按稳定拓扑顺序返回；
- 前序步骤失败时，下游步骤继续按确定性规则阻断；
- 并发线程复制 `ContextVar`，确保 `trace_id`、`session_id` 和 `user_id` 不丢失。

## 2. 计划身份与状态机

每个执行快照包含以下生命周期字段：

- `plan_id`：本地生成的唯一计划标识；
- `status`：`running`、`awaiting_confirmation`、`completed`、`failed`、
  `cancelled` 或 `expired`；
- `created_at`、`updated_at` 和 `expires_at`；
- `resume_count` 与 `max_resume_count`；
- `status_reason`：取消、过期或失败原因。

计划在恢复和重新持久化时保持同一个 `plan_id`。默认确认有效期由
`PLAN_TTL_SECONDS=900` 控制，最大恢复次数由 `PLAN_MAX_RESUME_COUNT=3` 控制。

## 3. 确认消费与崩溃保护

- 用户确认后先把计划写为 `running`，并增加恢复次数，再调用副作用工具；
- 如果进程在确认消费后退出，重启后的重复“确认”不会回退到 ReAct；
- 对处于 `running` 的计划重复确认会被确定性忽略；
- 待确认计划超过 TTL 后转为 `expired`，不执行副作用；
- 达到最大恢复次数后转为失败状态，要求重新发起请求。

该策略提供进程级的“避免自动重复执行”保护。跨系统严格幂等仍需要为外部副作用
适配器增加幂等键和事务记录。

## 4. 计划查询与取消 API

新增接口：

```text
GET    /v1/sessions/{session_id}/plan
DELETE /v1/sessions/{session_id}/plan
```

接口行为：

- 直接读取会话中的最新计划，不创建 Agent，不调用模型；
- 用户只能访问自己的会话计划；
- 只有 `awaiting_confirmation` 状态允许取消；
- 重复取消返回 `409 Conflict`；
- 查询过期的 `awaiting_confirmation` 或 `running` 计划时，持久化为 `expired`；
- 取消事件带有正确的用户和会话 Trace 上下文。

## 5. 代码结构

- `agent/strategies/models.py`：计划生命周期模型与状态转换；
- `agent/strategies/executor.py`：依赖层调度、有限并发和稳定结果汇总；
- `agent/chat.py`：确认消费、过期阻断和重启保护；
- `services/plans.py`：无模型依赖的计划会话服务；
- `api.py`：计划查询与取消接口；
- `security/auth.py`：`plan:cancel` 权限。
