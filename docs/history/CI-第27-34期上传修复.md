## 根因与修复

`pip-audit -r requirements.txt` 检出 `chromadb 0.6.3` 的 PYSEC-2026-3813/3814/3815。2026-10-25 查验 PyPI 最新稳定版仍为 1.5.9，上游公告也将其列为受影响版本，未给出可用修复版本：

- [跨租户授权缺失](https://osv.dev/vulnerability/PYSEC-2026-3813)
- [代码注入](https://osv.dev/vulnerability/PYSEC-2026-3814)
- [RBAC 范围校验缺失](https://osv.dev/vulnerability/PYSEC-2026-3815)

这些公告针对 Chroma 服务端路径，不能据此断言本项目嵌入式调用可被同样利用。交付包仍不继续分发已被标记的依赖：移除 Chroma 与其专用 PostHog 依赖，重新生成依赖闭包；工厂和直接构造 ChromaBackend 都在导入、模型调用和文件写入前明确拒绝。保留历史教学代码和用户数据，不静默把旧索引当成另一种格式。默认 Numpy 检索和版本化 SQL 知识平台继续可用。

复用旧配置时改用 `RAG_BACKEND=numpy`，从原始知识文档重建独立 JSON 索引。恢复 Chroma 支持必须先确认安全版本、兼容性和依赖/镜像审计，再移除停用保护；不建议手工安装被标记的版本。

原 CI 只审计宽松依赖范围，而镜像实际安装 `requirements-lock.txt`。补充精确锁文件审计后，发现以下旧锁版本也被漏洞数据库标记，并更新为通过此次审计的版本：

| 包 | 原锁版本 | 修复锁版本 |
|---|---|---|
| certifi | 2026.7.22 | 2026.10.23 |
| cryptography | 49.0.0 | 50.0.2 |
| PyJWT | 2.13.0 | 2.15.1 |
| opentelemetry-api / sdk | 1.44.0 | 1.45.1 |
| opentelemetry-semantic-conventions | 0.65b0 | 0.66b1 |

直接依赖设置对应安全下限。锁文件从 114 个包缩减为 58 个包；`packaging` 改为锁文件生成器的显式开发依赖，避免依赖 Chroma 间接安装。SBOM 也改用精确锁文件。保留 pip-audit 和 Trivy 的失败门禁，没有增加 CVE 忽略列表或失败放行。
