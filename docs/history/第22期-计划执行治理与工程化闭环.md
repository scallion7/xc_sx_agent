# 第 22 期：计划执行治理与工程化闭环

> 历史归档：记录当时的设计、实现与验收范围，不代表当前运行状态。当前入口见 [文档导航](../README.md) 与 [验收状态](../evaluation/acceptance.md)。原始证据保持原版本，不追改历史测量结果。

阶段 22 是当前压缩路线中的最终综合二次开发阶段。它不再只补充步骤超时、取消传播
和资源配额，而是把当前能够离线开发和验证的运行时治理、数据演进、安全适配、外部
系统契约、规则治理、运维诊断和质量门禁统一收口。

> 阶段状态：已完成；规划与完成日期：2026-08-23；开发与本地验收未访问真实模型、
> 真实身份提供方或真实支付/订单供应商。

## 1. 阶段目标

阶段 22 解决以下尚未闭环的问题：

1. 计划步骤没有运行中、超时、取消、跳过和重试状态；
2. 并发任务没有单步骤超时、实时取消传播、背压和资源预算；
3. 计划只保存当前快照，缺少独立运行尝试、执行租约和逐步骤检查点；
4. 进程中断后不能由新执行者安全接管正在运行的计划；
5. 工具只有只读/副作用分类，缺少超时、重试、并发组和输出上限策略；
6. 当前表结构依赖 `metadata.create_all()`，没有受控迁移和回滚验证；
7. 静态 Token 直接承担认证，缺少可替换的 OIDC/JWT 认证端口；
8. 退款与补偿仍绑定演示仓储，缺少供应商契约、回调和补偿执行框架；
9. 风险规则是单个 JSON 文件，缺少版本发布、试运行、激活和回滚；
10. 管理页缺少运行租约、资源消耗、超时、取消和恢复诊断；
11. 当前评估集偏向基础客服对话，缺少确定性计划、并发和故障恢复门禁；
12. 会话、计划、事件和售后日志没有统一的数据保留与清理入口。

阶段 22 完成后，项目的本地工程主线结束。后续只保留需要真实组织配置、真实供应商
账户、生产密钥或实际流量才能完成的部署验收。

## 2. 总体设计

```text
API / CLI / Agent
  → AuthProvider（静态 Token / OIDC JWT）
  → PlanLifecycleService
  → PlanRunService
      ├─ 执行租约与 fencing token
      ├─ CancellationToken
      ├─ ExecutionBudget
      ├─ ToolExecutionPolicy
      └─ 逐步骤检查点
  → PlanExecutor
      ├─ 有界调度 / 并发组 / fail-fast
      ├─ 单步骤与计划总超时
      ├─ 只读重试 / 熔断
      └─ 副作用前取消与权限复核
  → ToolManager
      ├─ 本地工具 / MCP
      ├─ OrderProvider / LogisticsProvider / RefundProvider
      └─ CompensationProvider

PlanRepository / PolicyRepository / OperationRepository
  ├─ JSON 兼容模式
  └─ SQL + Alembic 迁移

EventBus → 指标 / 管理台 / 故障评估 / CI 质量门禁
```

## 3. 工作包 A：计划运行时治理

### 3.1 完整步骤状态与运行记录

`PlanStepResult` 增加：

- `running`、`timed_out`、`cancelled`、`skipped`、`retrying` 状态；
- `started_at`、`completed_at` 和 `duration_ms`；
- `attempt_count`、`max_attempts` 和 `error_code`；
- `run_id`、`worker_id` 和 `termination_reason`；
- 工具调用次数、输出字节数和重试消耗。

新增 `PlanRun`，区分同一计划的首次执行、确认恢复、崩溃接管和人工恢复。SQL 新增
`plan_runs`；步骤每次尝试写入只追加的 `plan_step_attempts`，并同时保留计划事件，
不会覆盖旧证据。

### 3.2 逐步骤检查点

- 步骤进入 `running` 前保存运行快照；
- 完成、失败、超时或取消后立即保存结果；
- 已完成步骤在恢复时直接复用；
- 失败依赖的后续步骤持久化为 `skipped`；
- 检查点更新继续使用计划版本和乐观锁；
- 会话兼容快照不再作为运行恢复的权威来源。

### 3.3 执行租约与 fencing

- 每次运行生成 `run_id`、`worker_id` 和递增 fencing token；
- 执行者定期续租；
- 租约过期后允许管理员或新进程接管；
- 旧执行者恢复后不能再写入步骤或计划状态；
- 同一计划同时只能存在一个有效运行者；
- 接管过程记录 `plan.run.lease_expired/acquired/fenced/recovered` 事件。

### 3.4 超时、取消传播与竞争处理

- 单步骤超时；
- 计划总执行超时；
- CancellationToken 传播到调度器和支持协作取消的工具；
- 取消尚未启动的 Future；
- 副作用工具执行前再次读取取消状态、权限和 fencing token；
- 处理完成与取消、超时与取消、租约接管与旧执行者完成等竞争；
- 无法中断的外部请求完成后只允许记录受控结果，不继续调度后续步骤。

### 3.5 工具执行策略

新增 `ToolExecutionPolicy`：

| 字段 | 作用 |
|---|---|
| `timeout_seconds` | 单工具超时 |
| `retryable` | 是否允许通用重试 |
| `max_attempts` | 最大尝试次数 |
| `retry_backoff_seconds` | 重试退避 |
| `concurrency_group` | 工具级并发隔离 |
| `max_output_bytes` | 输出大小上限 |
| `circuit_breaker` | 是否启用熔断 |

订单、物流、政策等只读工具可以有限重试；创建工单、执行售后、补偿等副作用工具禁止
由通用执行器自动重试，继续使用各自的持久化幂等协议。

### 3.6 资源预算、背压与熔断

- 单计划最大工具调用次数；
- 单计划最大总耗时和累计重试次数；
- 单步骤与计划总输出大小；
- 最大并发槽位和排队步骤数；
- 按 `concurrency_group` 隔离本地、MCP、订单和知识检索工具；
- 同层关键步骤失败后的 fail-fast 与无效任务取消；
- 连续失败工具进入 `open`，冷却后进入 `half_open`；
- 预算耗尽或熔断时返回结构化错误码并阻断后续副作用。

## 4. 工作包 B：数据、安全与业务适配

### 4.1 Alembic 迁移与兼容升级

- 引入 Alembic 配置和首个基线迁移；
- 为现有会话、计划、计划事件、售后工单、操作日志和业务表建立迁移链；
- 新增 `plan_runs`、规则版本和数据维护所需表；
- SQLite 与 PostgreSQL 使用同一迁移入口；
- 提供 `upgrade`、`downgrade`、当前版本和迁移检查命令；
- CI 从空数据库升级到最新版本，并验证一次可逆降级；
- 保留教学模式自动建表开关，但 SQL 服务模式默认要求迁移版本正确。

### 4.2 可替换认证与 OIDC/JWT

新增 `AuthProvider` 协议：

- 保留静态 Token 作为本地开发模式；
- 增加 OIDC JWT 校验适配器；
- 校验 `issuer`、`audience`、签名、有效期和必要 scope；
- JWKS 缓存、刷新失败降级和未知 `kid` 处理；
- 将角色映射为现有细粒度权限；
- 管理操作记录身份来源、subject 和角色；
- 使用本地生成的测试密钥和 Fake JWKS 完成离线验收。

真实组织的 issuer、tenant、client、scope 和密钥轮换策略不在仓库内固化。

### 4.3 外部业务 Provider 契约

把演示仓储进一步拆分为：

- `OrderProvider`：订单查询和归属校验；
- `LogisticsProvider`：物流查询；
- `RefundProvider`：按幂等键提交、查询退款结果；
- `CompensationProvider`：按补偿操作键执行冲正或补发；
- `ProviderWebhookVerifier`：验证回调签名并标准化事件。

阶段内完成协议、SQL/Mock 适配器、超时、错误码映射、幂等查询、回调去重和契约测试。
真实供应商字段映射与账号联调仍需部署方提供文档和凭据。

### 4.4 补偿执行闭环

阶段 21 的补偿状态扩展为独立补偿操作：

- 稳定补偿幂等键；
- 人工确认后抢占执行租约；
- `pending/running/succeeded/failed/exhausted` 状态；
- 限制内重试、过期租约恢复和成功回放；
- 原退款操作和补偿操作双向关联；
- 管理员可登记人工完成，也可调用配置的 CompensationProvider；
- Mock/SQL 环境完整验证，未配置真实 Provider 时禁止伪造成功。

### 4.5 风险与政策版本治理

- `RiskRuleRepository` 和规则版本模型；
- draft、active、retired 生命周期；
- 规则 Schema 校验、版本 diff、试运行和影响统计；
- 激活新规则前必须由管理员确认；
- 支持回滚到上一 active 版本；
- 工单永久记录命中的规则版本；
- Policy RAG 对政策生效时间、失效时间和版本进行一致性校验；
- 管理台展示当前规则、候选规则和试运行结果。

## 5. 工作包 C：API、运维与数据生命周期

### 5.1 API 协议硬化

- 错误响应统一为带稳定 `error_code` 的 envelope；成功响应保留已有业务结构以兼容旧客户端；
- 全部响应返回 `request_id/trace_id`；
- 列表接口统一 cursor/limit 分页；
- 管理写操作支持请求幂等键；
- 对用户、管理员和高成本端点分别设置滑动窗口限流；
- 返回标准限流响应头和 `Retry-After`；
- 区分参数错误、权限错误、版本冲突、超时、配额和供应商失败；
- 保留旧接口兼容期，并在响应头标记弃用信息；
- OpenAPI 中补充权限、错误码和幂等语义。

### 5.2 配置分层与安全启动

- 增加 `development/test/production` 运行配置；
- 对超时、配额、保留期和并发数增加范围校验；
- production 模式禁止默认 Token、空密钥和演示数据；
- 敏感配置不进入健康检查、日志和异常响应；
- 启动时校验认证模式、数据库版本、Provider 和回调签名配置；
- 输出脱敏配置摘要和稳定诊断错误码；
- 提供 `.env.example`、最小开发配置和生产配置检查清单。

### 5.3 健康、就绪与诊断

- `/health` 只表示进程存活；
- `/ready` 检查数据库迁移版本、仓储、规则、Provider 和必要配置；
- `/v1/admin/diagnostics` 返回脱敏后的运行能力与降级状态；
- 区分可用、降级和不可用；
- Docker 健康检查改为就绪探针；
- CLI `doctor` 展示迁移、认证、Provider、规则和计划运行状态。

### 5.4 管理台与可观测性

- 计划运行列表、执行租约和 worker；
- 步骤耗时、尝试次数、超时和取消原因；
- 资源预算消耗和熔断器状态；
- 计划接管、恢复和 fencing 冲突时间线；
- 退款 Provider 与补偿操作状态；
- 风险规则版本、试运行和激活入口；
- 按用户、会话、计划、状态和时间筛选；
- 增加计划完成率、步骤超时率、取消请求、租约恢复、fencing 和副作用回放指标。

### 5.5 数据保留、备份与维护

- 为会话、计划、计划事件、运行记录、事件日志和售后操作配置保留期；
- 默认 dry-run 的维护 CLI；
- 按用户和时间分批清理终态数据；
- 活跃计划、待审工单、运行中操作和未完成补偿禁止清理；
- 清理动作写入审计事件；
- JSON 与 SQL 后端行为一致；
- 提供数据库备份前检查和 JSON sidecar 完整性检查；
- 提供脱敏导出、备份清单和恢复前校验；
- 使用临时 SQLite/JSON 数据完成备份恢复演练测试。

## 6. 工作包 D：故障注入、评估与 CI 门禁

### 6.1 固定计划数据集

- 执行中取消、重复取消和取消后的副作用阻断；
- 只读工具短暂失败后的有限重试；
- 副作用工具禁止通用重试；
- 工具调用、总耗时、重试和输出配额耗尽；
- 熔断器 closed/open/half-open；
- 进程中断、租约过期、接管和旧执行者 fencing；
- 重启后复用检查点；
- 单 Agent/Multi-Agent 路由与工具范围一致；
- 售后执行和补偿 exactly-once；
- OIDC 权限映射、过期 Token 和 JWKS 刷新；
- 空库迁移、兼容升级和受控降级；
- 规则试运行、激活和回滚；
- Provider 回调签名、去重和乱序事件；
- 数据清理 dry-run、保护规则和审计记录。

实际数据集中的每条案例都通过 `test` 字段映射到一个可执行的离线
`unittest`；质量脚本先运行映射测试，再将真实通过/失败结果聚合为指标，不使用模型
裁判，也不接受只在数据文件中预填“通过”的结果。

### 6.2 可控故障注入

新增离线故障工具和 Fake Provider，可确定性模拟：

- 固定延迟和永久阻塞；
- 第 N 次成功；
- 非法 JSON、超大输出和异常；
- 进程在步骤前后中断；
- 数据库版本冲突和短暂不可用；
- 回调重复、乱序和签名失败；
- JWKS 刷新失败；
- 规则文件损坏和迁移版本落后。

### 6.3 确定性指标

- `plan_completion_rate`；
- `timeout_detection_rate`；
- `cancellation_propagation_rate`；
- `budget_compliance_rate`；
- `checkpoint_reuse_rate`；
- `recovery_consistency_rate`；
- `route_stability_rate`；
- `side_effect_exactly_once_rate`；
- `migration_success_rate`；
- `auth_scope_accuracy`；
- `provider_idempotency_rate`；
- `policy_version_consistency_rate`。

涉及权限、副作用幂等、取消后副作用阻断、迁移一致性和用户隔离的安全指标必须达到
`1.0`，否则 CI 失败。

- 关键模块覆盖率门禁；
