# 第 20 期：独立计划仓储与审计

本阶段把阶段 17–19 保存在会话 `runtime_state` 中的单个计划快照，
升级为独立、可版本化、可查询和可审计的计划中心。单 Agent 与
Multi-Agent 使用同一个生命周期服务，旧会话数据在首次读取时自动迁移。

> 阶段状态：已完成；完成日期：2026-08-20；验收不访问真实或本地模型服务。

## 1. 设计目标

阶段 20 解决三个问题：

1. 会话快照只能保存最新计划，无法完整查询历史；
2. 单 Agent 和 Multi-Agent 各自实现恢复、记录和取消逻辑；
3. API 和管理台缺少步骤快照、状态迁移和版本冲突证据。

新的权威数据路径为：

```text
EcomAgent / MultiAgentOrchestrator
  → PlanLifecycleService
  → PlanRepository
      ├─ JSON: <session>.plans.json
      └─ SQL: plans + plan_steps + plan_events
  → 会话 runtime_state 兼容快照
```

`PlanRepository` 是计划状态的权威来源；`runtime_state` 仅作为旧数据和
旧代码的兼容层。

## 2. 计划、步骤与审计数据

SQL 后端新增三类数据结构：

| 结构 | 作用 | 关键字段 |
|---|---|---|
| `plans` | 计划当前快照 | `plan_id`、`session_key`、`user_id`、`status`、`version` |
| `plan_steps` | 步骤定义与执行结果投影 | 位置、工具、参数、依赖、状态、输出与错误 |
| `plan_events` | 只追加的审计时间线 | 事件类型、迁移前后状态、版本、时间和详情 |

JSON 后端使用每会话 sidecar 文件，在同一文档中保存 `plans` 和
`events`，避免把历史计划重新塞回对话文件。写入通过临时文件替换，
同进程并发更新使用文件级锁保护。

## 3. 乐观锁与计划版本

`PlanExecutionResult.version` 表示已持久化的计划版本：

- 新计划首次写入后为 `1`；
- 每次恢复、完成、失败、取消、过期或快照更新都递增版本；
- 更新时必须携带读取到的当前版本；
- SQL 使用 `WHERE plan_id = ? AND version = ?` 条件更新；
- 过期写入或重复确认会返回版本冲突，不覆盖新状态。

确认恢复仍遵守阶段 17 的安全顺序：先将 `awaiting_confirmation`
持久化为新版本的 `running`，再执行副作用工具。

## 4. 共用生命周期与兼容迁移

`PlanLifecycleService` 统一提供：

- 恢复最新计划；
- 记录新版本和审计事件；
- 检查 TTL 并持久化 `expired`；
- 按计划身份取消待确认计划；
- 同步旧 `latest_plan / pending_plan` 兼容快照。

如果独立仓储尚无记录，但旧会话中存在计划，服务会将其写入独立仓储
并记录 `plan.migrated` 事件。迁移后即使会话文件被删除，计划仍可从独立
仓储恢复和审计。

## 5. 查询、取消与用户隔离

保留阶段 18 的会话级接口：

- `GET /v1/sessions/{session_id}/plan`；
- `DELETE /v1/sessions/{session_id}/plan`。

新增独立计划接口：

- `GET /v1/plans`：查询当前用户的计划历史，支持 `session_id`、`status`
  和 `limit`；
- `GET /v1/plans/{plan_id}`：查询计划快照和完整审计时间线；
- `DELETE /v1/plans/{plan_id}`：按计划身份取消待确认计划；
- `GET /v1/admin/plans`：管理员查询全部用户计划；
- `GET /v1/admin/plans/{plan_id}`：管理员查询步骤与审计时间线。

普通 Token 只能查询和取消自己的计划；跨用户 `plan_id` 统一返回
`404`，避免泄露计划是否存在。管理台新增计划列表、步骤快照和版本迁移
时间线。

## 6. 代码结构

- `agent/strategies/models.py`：计划快照增加持久化版本；
- `repositories/plans.py`：仓储协议、JSON / SQL 适配器、乐观锁与审计模型；
- `infrastructure/database.py`：计划、步骤和审计事件表；
- `services/plans.py`：共用生命周期、旧快照迁移和 API 适配；
- `agent/base.py`：单/Multi-Agent 共用计划记录、恢复和取消入口；
- `bootstrap.py`：按后端构建或显式注入计划仓储；
- `api.py`：计划历史、详情、取消和管理员审计接口；
- `web/admin.html`：计划列表、步骤快照和审计时间线；
- `tests/test_plan_repository.py`：阶段 20 纯离线回归。
