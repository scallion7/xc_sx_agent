## 订单与物流查询流程

### 1. 确定目标订单

用户提供订单号时调用 `query_order`；没有时调用 `list_user_orders`，请用户选择。以服务端权限和查询结果为准，不能根据姓名、旧对话或其他用户的订单猜测访问权限。

### 2. 解释订单状态

报告工具实际返回的商品、金额和状态：

- 待发货：说明尚未发货；没有运单时不虚构物流轨迹或承诺发货日期。
- 已发货：查询物流进度。
- 已签收：按返回字段说明签收情况；缺少时间或地点时明确尚无对应信息。
- 退款相关状态：查询已有售后工单进度，区分处理中与已成功，不重复申请退款。
- 未识别状态或查询失败：保留服务端状态，解释暂时无法核实，不自行映射成成功。

### 3. 查询物流

调用 `query_logistics`，只报告实际返回的承运商、运单、轨迹和预计送达信息。可按时间顺序摘取最近 3–5 条事件；预计时间只是工具给出的估计，不承诺必达。

没有物流或轨迹时说明结果，并建议核对订单或稍后查询。订单是否拆包、是否有代收点、是否已催单，都需要实际证据，不能补全缺失字段。

### 4. 处理异常与政策问题

- 轨迹长期未更新：描述最近更新时间，建议人工核查；没有催单工具时不能声称已催单。
- 显示签收但用户未收到：说明系统记录与用户反馈不一致，建议核查签收凭证或转人工，不断言包裹已交本人。
- 配送时效、地区限制或售后诉求：调用 `search_knowledge`，传入用户明确选择的订单及已核实的适用条件，按引用回答；条件不全先追问。
- 用户改查另一订单时重新查询，不能沿用前一订单的物流、地域或授权。

订单和物流是本地演示或配置 Provider 返回的数据；仅表述本次查询可证实的内容，不把沙箱结果描述为真实承运商实时记录。
